INSTRUCCIONES PARA CONECTAR LA APP CON LA BASE DE DATOS / API

Este archivo explica cómo conectar la app Ionic/Angular de boletas escolares con una API o base de datos real.

Actualmente la app funciona con datos temporales llamados mock data. Estos datos se encuentran en:

src/app/core/mock-data/mock-school-data.ts

La app ya está preparada para trabajar de forma dinámica con:

- n padres de familia
- n hijos por padre
- n boletas por hijo
- n materias por boleta
- n comentarios por boleta
- n notificaciones por padre
- firma digital por boleta

Las pantallas ya consumen la información desde un servicio central:

src/app/core/services/school-data.service.ts

Por eso, para conectar la base de datos real, no se deben modificar directamente las páginas, sino principalmente el servicio.

============================================================
1. ARCHIVOS IMPORTANTES
============================================================

La estructura principal es:

src/app/core/
├── models/
│   └── school.models.ts
│
├── mock-data/
│   └── mock-school-data.ts
│
└── services/
    └── school-data.service.ts

------------------------------------------------------------
school.models.ts
------------------------------------------------------------

Define los modelos de datos que usa la app:

- ParentUser
- Student
- ReportCard
- SubjectGrade
- AppNotification
- TeacherComment

La API debe regresar datos con una estructura igual o muy parecida a estos modelos.

------------------------------------------------------------
mock-school-data.ts
------------------------------------------------------------

Contiene datos temporales para que la app funcione mientras no existe conexión real con base de datos.

Cuando la API esté conectada, este archivo puede quedarse como respaldo de pruebas o eliminarse.

------------------------------------------------------------
school-data.service.ts
------------------------------------------------------------

Este es el archivo principal que se debe modificar para conectar la API.

Actualmente obtiene datos desde los mocks, pero después debe obtenerlos mediante peticiones HTTP.

============================================================
2. ARCHIVOS QUE SE DEBEN MODIFICAR
============================================================

Para conectar la API/base de datos real, se deben modificar principalmente estos archivos:

src/app/core/services/school-data.service.ts
src/environments/environment.ts
src/app/app.config.ts

Opcionalmente, si la API regresa campos con nombres diferentes, también se puede modificar:

src/app/core/models/school.models.ts

============================================================
3. ARCHIVOS QUE IDEALMENTE NO SE DEBEN MODIFICAR
============================================================

Las páginas ya están conectadas al servicio, así que idealmente no se deben modificar estas pantallas:

src/app/parent/pages/dashboard/dashboard.page.ts
src/app/parent/pages/my-children/my-children.page.ts
src/app/parent/pages/report-cards/report-cards.page.ts
src/app/parent/pages/report-card-detail/report-card-detail.page.ts
src/app/parent/pages/notifications/notifications.page.ts
src/app/parent/pages/comments/comments.page.ts

Solo se deberían modificar si la API devuelve una estructura muy diferente a la esperada por los modelos.

============================================================
4. CONFIGURAR LA URL DE LA API
============================================================

Revisar o crear el archivo:

src/environments/environment.ts

Debe tener algo parecido a esto:

export const environment = {
  production: false,
  apiUrl: 'http://localhost:3000/api'
};

Cuando el backend esté desplegado, cambiar por la URL real:

export const environment = {
  production: true,
  apiUrl: 'https://api.escuela.com/api'
};

La variable environment.apiUrl será usada dentro de school-data.service.ts para construir las rutas de la API.

============================================================
5. ACTIVAR HTTPCLIENT
============================================================

En el archivo:

src/app/app.config.ts

Importar:

import { provideHttpClient } from '@angular/common/http';

Y agregarlo en providers:

providers: [
  provideIonicAngular(),
  provideRouter(routes),
  provideHttpClient()
]

Ejemplo completo:

import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideIonicAngular } from '@ionic/angular/standalone';
import { provideHttpClient } from '@angular/common/http';

import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideIonicAngular(),
    provideRouter(routes),
    provideHttpClient()
  ]
};

============================================================
6. MODIFICAR school-data.service.ts
============================================================

En el archivo:

src/app/core/services/school-data.service.ts

Descomentar o agregar estos imports:

import { HttpClient } from '@angular/common/http';
import { environment } from '../../../environments/environment';

Después activar el constructor:

constructor(private http: HttpClient) {}

Cuando se conecte la API, se deben eliminar los imports del mock:

import {
  MOCK_COMMENTS,
  MOCK_NOTIFICATIONS,
  MOCK_PARENTS,
  MOCK_REPORT_CARDS,
  MOCK_STUDENTS
} from '../mock-data/mock-school-data';

También se debe dejar de usar:

private currentParentId = 'parent-001';

Ese valor solo sirve para simular un padre mientras no hay login real.

============================================================
7. MÉTODOS QUE SE DEBEN CONECTAR A LA API
============================================================

Estos métodos del servicio deben reemplazar su lógica mock por peticiones HTTP:

- getCurrentParent()
- getStudentsByCurrentParent()
- getStudentById(studentId)
- getAllReportCardsByCurrentParent()
- getReportCardsByStudent(studentId)
- getReportCardDetail(studentId, reportCardId)
- getNotificationsByCurrentParent()
- markAllNotificationsAsRead()
- getCommentsByStudentAndReportCard(studentId, reportCardId)
- sendComment(studentId, reportCardId, message)
- signReportCard(reportCardId, signatureImage)

============================================================
8. EJEMPLO DE CAMBIO DE MOCK A API
============================================================

Método actual con mock:

getStudentsByCurrentParent(): Observable<Student[]> {
  const students = MOCK_STUDENTS.filter(
    student => student.parentId === this.currentParentId
  );

  return of(students);
}

Método conectado a API:

getStudentsByCurrentParent(): Observable<Student[]> {
  return this.http.get<Student[]>(
    `${environment.apiUrl}/parents/me/students`
  );
}

============================================================
10. RESPUESTAS ESPERADAS DE LA API
============================================================

------------------------------------------------------------
GET /auth/me
------------------------------------------------------------

Debe regresar el padre autenticado:

{
  "id": "parent-001",
  "fullName": "Nombre del padre de familia",
  "email": "padre@correo.com"
}

------------------------------------------------------------
GET /parents/me/students
------------------------------------------------------------

Debe regresar los hijos del padre autenticado:

[
  {
    "id": "student-001",
    "parentId": "parent-001",
    "fullName": "Nombre del estudiante",
    "grade": "6° Primaria",
    "average": 9.4,
    "performanceLevel": "Alto",
    "pendingReportCards": 1
  }
]

Debe funcionar con cualquier cantidad de hijos.

------------------------------------------------------------
GET /students/:studentId
------------------------------------------------------------

Debe regresar un estudiante específico:

{
  "id": "student-001",
  "parentId": "parent-001",
  "fullName": "Nombre del estudiante",
  "grade": "6° Primaria",
  "average": 9.4,
  "performanceLevel": "Alto",
  "pendingReportCards": 1
}

------------------------------------------------------------
GET /parents/me/report-cards
------------------------------------------------------------

Debe regresar todas las boletas de todos los hijos del padre autenticado:

[
  {
    "student": {
      "id": "student-001",
      "parentId": "parent-001",
      "fullName": "Nombre del estudiante",
      "grade": "6° Primaria",
      "average": 9.4,
      "performanceLevel": "Alto",
      "pendingReportCards": 1
    },
    "reportCards": [
      {
        "id": "report-001",
        "studentId": "student-001",
        "termName": "Primer Trimestre",
        "period": "Enero - Marzo 2026",
        "average": 9.4,
        "status": "Firmada",
        "subjects": []
      }
    ]
  }
]

Este endpoint se usa en:

/report-cards

------------------------------------------------------------
GET /students/:studentId/report-cards
------------------------------------------------------------

Debe regresar las boletas de un estudiante específico:

[
  {
    "id": "report-001",
    "studentId": "student-001",
    "termName": "Primer Trimestre",
    "period": "Enero - Marzo 2026",
    "average": 9.4,
    "status": "Firmada",
    "subjects": [
      {
        "id": "subject-001",
        "subjectName": "Matemáticas",
        "teacherName": "Nombre del profesor",
        "grade": 9.7,
        "performanceLevel": "Alto"
      }
    ]
  }
]

Este endpoint se usa en:

/report-cards/:studentId

------------------------------------------------------------
GET /students/:studentId/report-cards/:reportCardId
------------------------------------------------------------

Debe regresar el detalle de una boleta:

{
  "id": "report-001",
  "studentId": "student-001",
  "termName": "Primer Trimestre",
  "period": "Enero - Marzo 2026",
  "average": 9.4,
  "status": "Firmada",
  "subjects": [
    {
      "id": "subject-001",
      "subjectName": "Matemáticas",
      "teacherName": "Nombre del profesor",
      "grade": 9.7,
      "performanceLevel": "Alto"
    }
  ]
}

Este endpoint se usa en:

/report-card-detail/:studentId/:termId

Nota: en el frontend, termId realmente representa el reportCardId.

------------------------------------------------------------
GET /parents/me/notifications
------------------------------------------------------------

Debe regresar las notificaciones del padre autenticado:

[
  {
    "id": "notification-001",
    "parentId": "parent-001",
    "title": "Boleta disponible",
    "description": "Ya puede consultar la boleta del periodo.",
    "date": "2026-06-20",
    "type": "info",
    "icon": "ⓘ",
    "read": false
  }
]

Valores permitidos para type:

- warning
- info
- success

------------------------------------------------------------
PATCH /parents/me/notifications/read-all
------------------------------------------------------------

Debe marcar todas las notificaciones como leídas y regresar la lista actualizada:

[
  {
    "id": "notification-001",
    "parentId": "parent-001",
    "title": "Boleta disponible",
    "description": "Ya puede consultar la boleta del periodo.",
    "date": "2026-06-20",
    "type": "info",
    "icon": "ⓘ",
    "read": true
  }
]

------------------------------------------------------------
GET /students/:studentId/report-cards/:reportCardId/comments
------------------------------------------------------------

Debe regresar los comentarios de una boleta:

[
  {
    "id": "comment-001",
    "studentId": "student-001",
    "reportCardId": "report-001",
    "teacherName": "Nombre del profesor",
    "subjectName": "Matemáticas",
    "message": "Comentario del profesor.",
    "date": "2026-03-16T10:30:00"
  }
]

------------------------------------------------------------
POST /students/:studentId/report-cards/:reportCardId/comments
------------------------------------------------------------

Debe guardar un comentario nuevo.

Request esperado:

{
  "message": "Comentario escrito por el padre de familia."
}

Respuesta esperada:

{
  "id": "comment-002",
  "studentId": "student-001",
  "reportCardId": "report-001",
  "teacherName": "Padre de familia",
  "subjectName": "Comentario general",
  "message": "Comentario escrito por el padre de familia.",
  "date": "2026-06-20T15:40:00"
}

------------------------------------------------------------
POST /report-cards/:reportCardId/signature
------------------------------------------------------------

Debe guardar la firma digital.

Request esperado:

{
  "signatureImage": "data:image/png;base64,..."
}

Respuesta esperada:

{
  "success": true
}

Después de firmar, el backend debe actualizar el estado de la boleta a:

Firmada

============================================================
11. MÉTODOS SUGERIDOS PARA school-data.service.ts
============================================================

Cuando la API esté lista, los métodos del servicio pueden quedar así:

getCurrentParent(): Observable<ParentUser> {
  return this.http.get<ParentUser>(
    `${environment.apiUrl}/auth/me`
  );
}

getStudentsByCurrentParent(): Observable<Student[]> {
  return this.http.get<Student[]>(
    `${environment.apiUrl}/parents/me/students`
  );
}

getStudentById(studentId: string): Observable<Student> {
  return this.http.get<Student>(
    `${environment.apiUrl}/students/${studentId}`
  );
}

getAllReportCardsByCurrentParent(): Observable<
  { student: Student; reportCards: ReportCard[] }[]
> {
  return this.http.get<{ student: Student; reportCards: ReportCard[] }[]>(
    `${environment.apiUrl}/parents/me/report-cards`
  );
}

getReportCardsByStudent(studentId: string): Observable<ReportCard[]> {
  return this.http.get<ReportCard[]>(
    `${environment.apiUrl}/students/${studentId}/report-cards`
  );
}

getReportCardDetail(
  studentId: string,
  reportCardId: string
): Observable<ReportCard> {
  return this.http.get<ReportCard>(
    `${environment.apiUrl}/students/${studentId}/report-cards/${reportCardId}`
  );
}

getNotificationsByCurrentParent(): Observable<AppNotification[]> {
  return this.http.get<AppNotification[]>(
    `${environment.apiUrl}/parents/me/notifications`
  );
}

markAllNotificationsAsRead(): Observable<AppNotification[]> {
  return this.http.patch<AppNotification[]>(
    `${environment.apiUrl}/parents/me/notifications/read-all`,
    {}
  );
}

getCommentsByStudentAndReportCard(
  studentId: string,
  reportCardId: string
): Observable<TeacherComment[]> {
  return this.http.get<TeacherComment[]>(
    `${environment.apiUrl}/students/${studentId}/report-cards/${reportCardId}/comments`
  );
}

sendComment(
  studentId: string,
  reportCardId: string,
  message: string
): Observable<TeacherComment> {
  return this.http.post<TeacherComment>(
    `${environment.apiUrl}/students/${studentId}/report-cards/${reportCardId}/comments`,
    { message }
  );
}

signReportCard(
  reportCardId: string,
  signatureImage: string
): Observable<{ success: boolean }> {
  return this.http.post<{ success: boolean }>(
    `${environment.apiUrl}/report-cards/${reportCardId}/signature`,
    { signatureImage }
  );
}

============================================================
12. AUTENTICACIÓN Y SEGURIDAD
============================================================

Actualmente el frontend usa un padre simulado:

private currentParentId = 'parent-001';

Eso solo es temporal.

Cuando exista login real:

1. El padre inicia sesión.
2. El backend regresa un token o crea una sesión.
3. La app guarda el token.
4. Las peticiones usan el usuario autenticado.
5. El backend identifica qué padre está consultando.

Importante:

Aunque el frontend mande un studentId, el backend debe validar que ese estudiante realmente pertenezca al padre autenticado.

Un padre no debe poder consultar hijos, boletas, comentarios o notificaciones de otro padre.

============================================================
13. VALIDACIONES NECESARIAS EN BACKEND
============================================================

El backend debe validar:

- El padre autenticado existe.
- El estudiante pertenece al padre autenticado.
- La boleta pertenece al estudiante correcto.
- La firma corresponde a una boleta válida.
- Los comentarios se guardan en la boleta correcta.
- Las notificaciones pertenecen al padre autenticado.

============================================================
14. PRUEBAS DESPUÉS DE CONECTAR LA API
============================================================

Después de conectar la API, probar:

1. Login correcto.
2. Dashboard muestra el nombre del padre real.
3. Dashboard muestra el número real de boletas pendientes.
4. Dashboard muestra el número real de notificaciones no leídas.
5. Mis hijos muestra todos los hijos del padre autenticado.
6. Si un padre tiene 1 hijo, se muestra 1.
7. Si un padre tiene n hijos, se muestran todos.
8. Boletas desde sidebar muestra todas las boletas de todos sus hijos.
9. Boletas desde un hijo muestra solo las boletas de ese hijo.
10. Detalle de boleta muestra materias y calificaciones correctas.
11. Firmar boleta guarda la firma correctamente.
12. Después de firmar, la boleta cambia a Firmada.
13. Comentarios muestra comentarios correctos de esa boleta.
14. Enviar comentario guarda el comentario.
15. Notificaciones muestra solo las del padre autenticado.
16. Marcar todas como leídas actualiza el estado.
17. Un padre no puede ver hijos ni boletas de otro padre.

============================================================
15. SI LA API USA OTROS NOMBRES DE CAMPOS
============================================================

Si la API regresa campos diferentes, hay dos opciones.

------------------------------------------------------------
Opción A: adaptar el backend
------------------------------------------------------------

Hacer que la API regrese los nombres como los modelos del frontend.

Ejemplo:

{
  "fullName": "Juan Pérez",
  "grade": "6° Primaria"
}

------------------------------------------------------------
Opción B: mapear los datos en el servicio
------------------------------------------------------------

Si la API regresa algo como:

{
  "nombreCompleto": "Juan Pérez",
  "grado": "6° Primaria"
}

entonces se debe transformar la respuesta dentro de school-data.service.ts.

Ejemplo:

import { map } from 'rxjs';

getStudentsByCurrentParent(): Observable<Student[]> {
  return this.http.get<any[]>(
    `${environment.apiUrl}/parents/me/students`
  ).pipe(
    map(response => response.map(item => ({
      id: item.id,
      parentId: item.parent_id,
      fullName: item.nombreCompleto,
      grade: item.grado,
      average: item.promedio,
      performanceLevel: item.nivel,
      pendingReportCards: item.boletasPendientes
    })))
  );
}

16. RESUMEN FINAL
============================================================

Para conectar la app con base de datos real se debe trabajar principalmente en:

src/app/core/services/school-data.service.ts

El compañero encargado debe:

1. Configurar environment.apiUrl.
2. Activar provideHttpClient().
3. Descomentar o agregar HttpClient en SchoolDataService.
4. Reemplazar métodos mock por peticiones HTTP.
5. Confirmar que la API regrese datos compatibles con school.models.ts.
6. Validar en backend que cada padre solo vea su propia información.
7. Probar dashboard, hijos, boletas, detalle, comentarios, firma y notificaciones.

La app ya está preparada para que la conexión con base de datos sea más sencilla. Las pantallas ya consumen un servicio central, por lo que no debería ser necesario rehacer la interfaz.
